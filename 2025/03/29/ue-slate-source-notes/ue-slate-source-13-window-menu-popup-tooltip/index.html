系列定位：UE5 Slate 原理与源码拆解（UE5.7）
本篇只抓一件事：把弹层问题放回窗口和菜单栈。

弹层不是普通子控件

菜单关不掉、Tooltip 残留、Popup 被挡住，这些问题表面像小控件毛病，实际经常落在窗口层级和菜单栈。Slate 的弹层不是永远在父控件里画一层，有些会进入窗口系统，焦点和输入路径也会跟着改。

这一篇从 SWindow 和 FMenuStack 读弹层。我的重点不是菜单 API 怎么用，而是它们如何创建、置顶、接输入、失焦关闭，以及关闭后怎么恢复原来的焦点路径。

菜单和 Tooltip 的问题一旦进入窗口层，就不能只按父子控件树理解。焦点、置顶、外部点击关闭，都是窗口系统和菜单栈一起决定的。

别把 Popup 都想成 Paint 出来的

不要以为 Popup 一定是父控件 OnPaint 画出来的。很多 Slate 弹层会进入窗口系统，输入和层级不再只由原来的控件父子关系决定。

菜单和 Tooltip 问题

  • 弹层被挡住时先判断它是窗口还是同窗口层级。
  • 菜单不关闭时追 DismissAllMenus 和外部点击路由。
  • Tooltip 残留时检查悬停路径和窗口焦点变化。
  • 多显示器问题同时查窗口位置和 DPI 缩放。

源码流程框架

  1. 普通控件里的菜单入口通常会调用 FSlateApplication::PushMenu 或走 SMenuAnchor。
  2. PushMenu 会把内容包装成菜单窗口或弹层内容，并交给 FMenuStack 管理。
  3. FMenuStack 维护当前打开的菜单层级，负责子菜单、父菜单、点击外部关闭、焦点恢复等规则。
  4. 菜单内容需要 Prepass 才能知道期望尺寸，MenuStack.cpp 里会对 WrappedContent 做布局预处理。
  5. Tooltip 与 Cursor Decorator 等也可能有独立窗口或特殊绘制路径，并由 FSlateUser 维护状态。
  6. 关闭菜单时不仅销毁窗口/内容，还要处理捕获、焦点、路径恢复，否则下一次输入会落到奇怪目标。

几个细节拆开看

菜单是栈，不是单个窗口

子菜单展开时，旧菜单不能立刻消失，但点击外部又要能一口气关闭整串菜单。这就是 FMenuStack 的意义：它维护的是一组有关联的临时 UI，而不是一个孤立 Popup。

弹层尺寸也要 Prepass

菜单内容打开前要先知道尺寸，才能决定弹出方向、屏幕边界避让和窗口大小。所以弹层不是“点了以后直接画”，它也要走布局测量，只是生命周期更短。

焦点恢复是弹层 bug 高发点

菜单关闭后焦点应该回到哪里？如果打开菜单前路径没保存好，或者关闭时输入捕获没释放，下一次键盘/鼠标事件就可能落在已经消失的控件路径上。

先把层级讲明白

弹层读完以后，菜单和 Tooltip 就不该再被当成普通子控件。它们经常有窗口身份，也就会有窗口级别的焦点和层级问题。
