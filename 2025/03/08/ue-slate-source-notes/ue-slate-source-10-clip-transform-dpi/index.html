系列定位：UE5 Slate 原理与源码拆解（UE5.7）
本篇只抓一件事：把错位问题拆成坐标系问题。

差两个像素也要讲证据

UI 偏两个像素这种问题最容易把人逼疯，因为它看起来小，背后却可能牵着一串坐标系。Slate 里有布局变换、渲染变换、裁剪空间、窗口缩放、DPI 缩放，任何一层没对齐，最后都可能变成“怎么就是差一点”。

这一篇不追具体控件，而是追 FGeometry、Clip 和 DPI。我的经验是，错位问题不要先凭眼睛猜，要先把当前坐标属于哪一层讲清楚。否则调一个偏移量，只是在和另一个隐藏偏移量拔河。

错位问题最像玄学，其实是因为我们经常混用坐标系。只要把当前值属于布局、窗口还是渲染空间说清楚，很多偏移就不神秘了。

别拿屏幕坐标倒推一切

不要拿最终屏幕坐标倒推所有布局问题。屏幕空间只是结果，布局空间、窗口空间和渲染空间之间经过了多次变换；你得先知道自己手里那组数是哪一层的。

错位和发虚

  • 错位时同时打印 AbsolutePosition、LocalSize 和 Scale。
  • 发虚时检查非整数缩放和半像素偏移。
  • 被裁剪时沿裁剪栈找第一个过小的 ClipZone。
  • DPI 问题要查窗口和应用缩放，不只改控件大小。

源码流程框架

  1. 布局阶段产生的 FGeometry 包含 LocalSize、AbsolutePosition、LayoutTransform 等信息。
  2. 绘制阶段会从 Geometry 生成 FPaintGeometry，再交给 DrawElement。这里可能叠加 RenderTransform。
  3. 裁剪由 FSlateClippingManager 管理，父控件或窗口会 Push Clip，子控件绘制时继承或修改裁剪栈。
  4. 窗口根部会乘 ApplicationScale 和窗口 DPI Scale，Prepass 与 Paint 都会受到这个比例影响。
  5. 非整数缩放、半像素位置、RenderTransform 会影响最终采样，导致 UI 看起来发虚。
  6. 命中测试使用的几何和裁剪也受这些变换影响，所以视觉错位可能同时伴随点击区域错位。

几个细节拆开看

LayoutTransform 和 RenderTransform 别混

LayoutTransform 参与布局空间推导，RenderTransform 更偏绘制阶段的附加变化。用 RenderTransform 做动画通常不会让父容器重新给空间；用布局参数改尺寸则会触发完全不同的失效路径。

Clip 是栈，不是单个矩形

很多裁剪问题不是当前控件裁剪错，而是祖先控件早就 Push 了一个更小的 ClipZone。查被裁掉时要沿裁剪栈往上找第一个收窄的位置。

DPI 会让“整数坐标”失效

局部空间里看着是整数，乘上 DPI 或 ApplicationScale 后可能变成非整数。像素对齐问题要看最终 PaintGeometry，而不是只看控件本地坐标。

这一篇的停靠点

坐标问题读到这里，至少别再只凭肉眼调偏移量。先把坐标空间讲明白，再谈修正，才不会越补越歪。
