系列定位：UE5 Slate 原理与源码拆解（UE5.7）
本篇只抓一件事：把样式读成资源生命周期问题。

图标丢了，先查生命周期

编辑器插件里最烦的 UI 资源问题，不是“图标不好看”，而是开发期能显示，打包后丢；热重载后偶现丢；运行久了内存涨。最后查来查去，往往不是路径一处写错，而是 StyleSet、Brush 和 Renderer 资源生命周期没对齐。

这一篇读 FSlateStyleSet、FSlateBrush 和动态图片 Brush。Slate 样式不是单纯皮肤表，它同时决定资源如何被找到、如何被引用、何时被释放。这个边界不清楚，UI 资源问题会特别像幽灵。

样式系统很容易被写成“路径表”。但在插件和热重载场景里，它更像生命周期管理：什么时候注册，谁还拿着引用，什么时候注销。

这篇只看 Style 和 Brush

版本先钉在 C:\Epic\UE_5.7。这篇只读 Slate 内核相关路径，UMG 只在必要时拿来说明“外面怎么接进来”。

资源从注册到使用

样式和资源入口

源码位置 关键符号 备注
SlateCore/Public/Styling/SlateStyle.h FSlateStyleSet 样式集合
SlateCore/Public/Styling/SlateBrush.h FSlateBrush 绘制资源描述
SlateCore/Private/Brushes/SlateDynamicImageBrush.cpp FSlateDynamicImageBrush 动态图 Brush
SlateCore/Public/Styling/SlateStyleRegistry.h FSlateStyleRegistry 样式注册表

Brush 不是贴图本体

不要把 FSlateBrush 当成已经在 GPU 上的贴图。Brush 更像一张资源说明书，真正渲染资源要等 Slate Renderer 根据它去查找或创建。

查资源失踪

  • 图标丢失先查 StyleSet 是否注册、路径是否进包。
  • 模块卸载前注销样式，避免控件继续引用旧 Brush。
  • 动态图反复创建时检查是否复用 Brush 和释放资源。
  • 编辑器热重载后重点查 StyleSet 名字冲突。

源码流程框架

  1. 模块启动时创建 FSlateStyleSet，设置 ContentRoot，并用 FSlateStyleRegistry::RegisterSlateStyle 注册。
  2. 控件通过 Style 名称或 FSlateIcon 查找 Brush，拿到的是 FSlateBrush 描述。
  3. FSlateBrush 记录 DrawType、ResourceName、ImageSize、Margin、Tiling、Tint、ResourceObject 等信息。
  4. 绘制阶段 Brush 会进入 DrawElement，Renderer 根据 Brush 的资源描述查找或创建 Slate Resource。
  5. FSlateDynamicImageBrush 可以绑定运行时纹理或名字，但要考虑资源注册、释放和引用寿命。
  6. 模块 Shutdown 时必须注销 StyleSet；否则热重载或卸载后可能留下旧 Brush 引用。

几个细节拆开看

Brush 是描述，不是所有权答案

一个 FSlateBrush 可能指向资源名，也可能指向 UObject ResourceObject。它自己不等于“我安全持有了贴图”。资源到底活多久，要看 StyleSet、模块、UObject 和 Renderer 资源缓存的组合。

StyleSet 名字是全局键

编辑器插件里 StyleSet 名字冲突或重复注册，会让图标查找结果变得很怪。热重载尤其容易留下旧注册。Shutdown 里注销，不是洁癖，是避免下一次加载拿到旧资源。

动态图片最怕反复创建

运行时头像、缩略图、外部图片如果每次都 new 一个 DynamicImageBrush，又没有复用和释放策略，内存和渲染资源都会涨。这里要把 Brush 缓存和资源清理当成同一件事设计。
