最后回到自己写控件

自定义 Slate 控件写到最后，真正考验的不是会不会 SNew。考验的是你有没有尊重 Slate 的协议：生命周期别假装是 UObject，布局要正确回答尺寸，绘制只记 DrawElement，输入用 FReply 明确副作用，资源交给 Style 管，性能要能被工具证明。

这一篇算是收官。我会用自定义控件把前面的输入、布局、绘制、失效、资源和调试串起来。读完之后，至少应该知道什么时候继承 SCompoundWidget，什么时候写 SLeafWidget，什么时候必须上 SPanel。

写自定义控件最能暴露前面有没有读懂：布局、输入、绘制、资源、失效，哪一层偷懒，最后都会以很具体的 bug 回来找你。

自定义控件的骨架

源码位置 关键符号 备注

别全都继承 SCompoundWidget

不要为了省事全部继承 SCompoundWidget。需要自绘就考虑 SLeafWidget，需要控制多个子控件布局就用 SPanel；基类选错，后面的布局、性能和维护都会别扭。

真出事时

  • 崩溃先查引用生命周期和 Lambda 捕获。
  • 泄漏先查共享指针环和 Style/Brush 注销顺序。
  • 焦点灾难先查 FReply 副作用和 MouseCapture。
  • 绘制异常按 Geometry、Clip、Layer、Batch 四层排查。

源码流程框架

  1. 如果控件只是包一层现有子控件，优先继承 SCompoundWidget，在 ChildSlot 里组织内容。
  2. 如果控件没有子控件、主要靠自绘，考虑 SLeafWidget，自己实现 ComputeDesiredSize 和 OnPaint。
  3. 如果控件要管理多个子控件的布局规则，继承 SPanel，实现 Children、OnArrangeChildren、ComputeDesiredSize。
  4. 输入回调里只做必要状态改变，副作用通过 FReply 明确表达，不要偷偷改全局焦点。
  5. 绘制只写 DrawElement，不在 OnPaint 里加载资源、创建大对象或改业务状态。
  6. 属性变化要给正确失效理由，资源引用走 Style/Brush 生命周期，性能问题用工具留基线。

几个细节拆开看

基类选择决定后面复杂度

很多控件一开始用 SCompoundWidget 很顺，后来想自定义布局、插多个 Slot、控制子控件排列，就会越写越别扭。基类不是形式问题，它决定你参加 Slate 哪几套协议。

自绘控件最少要守住两件事

一是 ComputeDesiredSize 要稳定回答尺寸愿望；二是 OnPaint 只描述绘制。尺寸每帧抖、Paint 里改状态，是自绘控件最常见的两个坑。

排障顺序比经验更可靠

崩溃先看引用和 Lambda，泄漏先看共享指针环，焦点先看 FReply 和 Capture，绘制先看 Geometry / Clip / Layer / Batch。按这个顺序来，至少不会在错误层里耗半天。
