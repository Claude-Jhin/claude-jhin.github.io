系列定位：UE5 Slate 原理与源码拆解（UE5.7）
本篇只抓一件事：把 SWidget 当成轻量 C++ 对象图来读。

先适应这套对象观

从 UMG 过来读 Slate，最别扭的地方就是：这里没有 UObject 那套熟悉的生命周期。没有 BeginPlay，没有 GC 标记，很多东西靠 TSharedRef、SNew、Construct 和 Attribute 自己把关系织起来。第一次看会觉得“这也太 C++ 了”，但这恰好是 Slate 的味道。

这一篇不追某个具体控件，而是读 SWidget 的对象模型。它的重点不是“怎么创建一个控件”，而是为什么 Slate 能用声明式语法搭出控件树，又能用属性失效把状态变化传回布局和绘制系统。

SWidget 的难点不是语法，而是它没有 UObject 那种强仪式感生命周期。你得从引用、Slot、Attribute 和 Invalidate 的组合里看它怎么活。

这篇不聊 GC

源码按 C:\Epic\UE_5.7 来。这里更看重调用位置和职责边界，不看重精确行号；如果你用 5.5，对着符号搜会比对着行号找靠谱。

别把 UObject 习惯带太深

不要给 SWidget 硬套 UObject 生命周期。Slate 控件的释放顺序、闭包捕获、弱引用和属性失效，都得按引用计数对象图来理解。尤其在 Lambda 里捕 UObject，别让“看起来还能用”的指针把你骗了。

写控件时我会检查

  • 自定义控件先确认 Construct 里是否建立了稳定的 ChildSlot。
  • 崩溃时优先看 Lambda 捕获和共享指针环。
  • 属性不刷新时查 TSlateAttribute 是否声明了正确的失效理由。
  • 不要把 Construct 当成显示/隐藏都会触发的钩子。

源码流程框架

  1. 声明式创建从 SNew / SAssignNew 开始，宏会构造对应 Widget 的 FArguments，再调用控件的 Construct。
  2. Construct 里通常会保存 Attribute、设置 Slot、构造子控件。这里不是 UObject 构造函数，更像 Slate 控件的装配阶段。
  3. 控件树通过 TSharedRef<SWidget> 和各种 Slot 持有。SCompoundWidget 常见是一条 ChildSlot，SPanel 则维护多个子 Slot。
  4. 属性如果使用 TSlateAttribute / managed attribute，会带着失效理由参与后续更新。属性变化不是单纯赋值，而是可能触发布局或绘制失效。
  5. 生命周期靠引用计数和父子持有关系自然结束。没有 GC 扫描，也没有 UObject 的反射生命周期。
  6. UMG 包装 Slate 时，要格外注意 UObject 生命周期和 Slate 引用生命周期不一致。

几个细节拆开看

Construct 不是构造函数

Slate 控件的 C++ 构造函数通常很薄，真正装配发生在 Construct(const FArguments&)。这就是为什么很多状态必须在 Construct 参数里传进去，而不是指望 UObject 那种构造后再初始化的流程。

Attribute 的价值是“知道改了什么”

普通成员变量变了，Slate 不一定知道该重算什么；Attribute 绑定了失效理由，系统才知道是 Paint 失效、Layout 失效，还是 Volatility 变化。读 SlateAttribute.h 时要重点看它和 EInvalidateWidgetReason 的关系。

共享指针让环引用变成真实风险

Slate 很方便用 Lambda 捕获 SharedThis(this)，但这也是泄漏来源。控件持有委托，委托捕获控件自己，引用计数就可能闭环。自定义控件里我更愿意用弱引用，尤其是跨帧回调或 ActiveTimer。

留一个判断

SWidget 这层读顺以后，Slate 的语法就没那么吓人了。它不是“没有生命周期”，只是生命周期不按 UObject 的仪式走。
