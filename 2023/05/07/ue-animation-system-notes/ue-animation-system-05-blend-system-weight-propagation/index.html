核心问题

“动作不自然”很多时候不是资源问题，而是权重传播链不可解释。
你要能回答三件事：

  1. 时间怎么推进（Sequence/AssetPlayer）。
  2. 样本怎么分权（BlendSpace）。
  3. 骨骼怎么分层（LayeredBlendPerBone）。

只要其中一层不可解释，最终观感就会漂。

深入拆解：权重如何一路传下去

1) SequencePlayer：先有“时间可信”，再谈“姿态可信”

UpdateAssetPlayer 会把当前序列、播放速率、循环信息写入 TickRecord。
而真正与同步组相关的记录在 CreateTickRecordForNode（AssetPlayerBase）里完成。

关键结论：

  • 同步组信息是在 Update 阶段建立的。
  • Evaluate 只是消费这个时间与同步结果。

所以“脚步相位飘了”优先查 TickRecord/SyncGroup，而不是先怪 BlendSpace。

2) BlendSpace：不是简单插值，而是“样本集合管理”

UBlendSpace::GetSamplesFromBlendInput 会基于输入获取样本及权重，之后归一化。
TickAssetPlayer 还要处理：

  • 样本权重插值（Old/New sample data 过渡）。
  • Marker Sync 跟随与 Leader 选择。
  • Notify 与 RootMotion 的样本级汇总。

这解释了一个常见现象：你以为只是调了速度轴，实际上还改了同步领导样本，导致整套步态节奏变化。

3) LayeredBlendPerBone：骨骼掩码不是“二值开关”

FAnimNode_LayeredBoneBlend 在 Update 阶段会更新 DesiredBoneBlendWeights，再用 UpdateDesiredBoneWeight 平滑到 CurrentBoneBlendWeights。
Evaluate 阶段调用 BlendPosesPerBoneFilter 执行按骨骼过滤混合。

关键点：

  • 每根骨骼有来源索引与权重，不是简单“上半身=1，下半身=0”。
  • 根骨权重会影响 Root Motion 归属（bBlendRootMotionBasedOnRootBone 路径）。

4) Curve 与 Attribute 也在混合链里

很多人只盯姿态骨骼，忽视曲线。BlendPosesPerBoneFilter 同时会处理曲线与属性。
于是会出现“姿态看着对，但 IK 曲线错”的问题。

常见故障模式与直接排法

  1. 观感突然“打折”：查某层权重是否被固定为 0/1。
  2. 步态节奏漂移：查 BlendSpace 领导样本切换与 SyncGroup。
  3. 上半身动作污染下半身：查 LayeredBlend 掩码与骨链根节点。
  4. Root Motion 不稳定：查根骨混合权重与 Slot/Layer 覆盖顺序。

最小验证步骤

  1. 先只保留一个 SequencePlayer，记录基线（步态、曲线、RootMotion）。
  2. 接入 BlendSpace，逐步扫速度/方向输入，打印样本权重分布。
  3. 接入 LayeredBlendPerBone，只启用一条骨链（如脊柱），验证影响范围。
  4. 把每层权重分别固定成 0 或 1 做隔离测试，定位污染层。
  5. 打印同步组与 TickRecord 关键字段，确认节奏来源可解释。
  6. 形成“节点级权重解释表”：输入 -> 样本 -> 层权重 -> 输出。

预期结果：你能把“动作看起来不自然”拆成一条可测量的权重链。

小结

Blend 体系的本质不是“多个动画混一下”，而是“时间、样本、骨骼、曲线的联合求值”。
当每一级权重都可解释时，质量问题会从主观审美争论变成客观工程调参。
