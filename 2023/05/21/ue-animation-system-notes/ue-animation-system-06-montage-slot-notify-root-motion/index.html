核心问题

Montage 系统难点不在“播出来”，而在“播出来以后不破坏主动画流一致性”。
常见线上事故：

  1. 上半身技能把下半身也污染。
  2. Notify 触发时间漂移，玩法事件与画面错拍。
  3. Root Motion 与 CharacterMovement 叠加不一致，出现滑步或瞬移。

这篇要打通四条链：Montage 生命周期、Slot 混合、Notify 事件、Root Motion 回写。

深入拆解：四条链怎么互相约束

1) Montage 生命周期：权重推进和时间推进是两件事

Montage_UpdateWeight 与 Montage_Advance 分别负责权重变化与播放位置推进。
这意味着“看起来在播”不等于“权重已进入有效覆盖区间”。

工程上要同时看：

  • Montage Position 是否前进。
  • Slot Weight 是否真正影响最终姿态。

2) Slot 节点决定“插入位置”，不是单纯开关

FAnimNode_Slot::Update_AnyThread / Evaluate_AnyThread 决定 Montage 在图中的混合语义。
同一个 Montage 放在不同 Slot 位置，结果完全不同：

  • 靠前：更像覆盖基础动作。
  • 靠后：更像叠加细节层。

所以“Montage 破坏 locomotion”常常是 Slot 拓扑问题，不是 Montage 资源问题。

3) Notify：画面时间线事件，不是权威玩法时钟

QueueMontageBlendingOutEvent、QueueMontageEndedEvent 体现了 Notify/Event 的排队语义。
正确姿势是：

  • 把 Notify 当作动画时间线信号。
  • 高权威玩法仍由服务端逻辑确认。

否则网络延迟下就会出现“客户端已经砍中，服务端还没认”的错位体验。

4) Root Motion：动画位移必须回写到移动系统

UAnimMontage::ExtractRootMotionFromTrackRange 提取的是动画位移增量；
真正生效要经过 CharacterMovement：

  • TickCharacterPose 中 ConsumeRootMotion() 获取增量。
  • PerformMovement 和 ApplyRootMotionToVelocity 将其合并进最终速度/位移。

只看 AnimInstance 而不看 Movement，是 Root Motion 排障最常见盲区。

常见故障与快速定位

  1. 技能播了但肢体错层：优先查 Slot 在图中的位置和 LayeredBlend 骨链。
  2. Notify 早/晚一拍：查 Montage Position 与队列分发时序。
  3. 滑步或冲刺过头：查是否重复消费 Root Motion，或与 RMS（RootMotionSource）叠加冲突。
  4. 中断后残留姿态：查 Montage Stop/BlendOut 路径与状态机回收时机。

最小验证步骤

  1. 做一个只影响脊柱以上的攻击 Montage，Slot 放在可控位置。
  2. 在 Montage_Advance 与 Slot::Evaluate_AnyThread 打断点，确认时间推进与姿态覆盖同帧一致。
  3. 关键 Notify 打印：帧号、Montage Position、业务事件触发时间。
  4. 开/关 Root Motion 对照测试：
    观察胶囊位移、角色位移、动画位移是否三者一致。
  5. 在 CharacterMovement::ApplyRootMotionToVelocity 观察最终速度变化，排查重复叠加。
  6. 做一次中断场景（受击/翻滚）回归，确认 BlendOut 后状态干净回收。

预期结果：你会得到一条“技能动画接入主流”的稳定模板，避免动画与玩法脱节。

小结

Montage 不是孤立系统，它同时触达 Pose、事件与移动。
只要把 Slot 插入位置、Notify 语义、Root Motion 消费路径三者统一管理，技能动画就能稳定扩展而不反复返工。
