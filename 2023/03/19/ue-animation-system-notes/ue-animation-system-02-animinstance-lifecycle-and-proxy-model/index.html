本文主题：拆清 AnimInstance 与 Proxy 的职责分工，以及线程安全边界（源码长文版）

核心问题

UE5 动画并行化后，最容易导致“偶发错态、偶发崩溃、偶发抖动”的根因，不是节点本身，而是线程边界被打破。
这篇只回答一个问题：什么数据该放在 UAnimInstance，什么数据该进入 FAnimInstanceProxy，以及每帧在哪个阶段读写它们。

主线图

生命周期与线程边界：逐段拆

1) Initialize：对象语义建立 + 运行时结构就绪

InitializeAnimation 会做两类事情：

  1. UObject 语义：绑定 Mesh、Skeleton、初始变量、蓝图初始化事件。
  2. 运行时语义：Proxy 初始化、节点实例内存准备、RequiredBones 等缓存准备。

这一步是“拓扑就绪”。如果初始化时角色资源不一致（Skeleton 不匹配、Linked Layer 类错配），后续很多错误会在 Evaluate 才暴露。

2) Update：推进“状态与时间”，不是直接算最终 Pose

NativeUpdateAnimation 典型在 GameThread 执行，你会在这里采样：

  • 速度、加速度、落地状态。
  • 武器/技能状态。
  • GameplayTag 或行为树状态快照。

FAnimInstanceProxy::UpdateAnimation 进一步把这些数据推进到可评估状态，期间会尝试调用 NativeThreadSafeUpdateAnimation（:1320）。这里是你把“可纯函数化”的逻辑迁移到线程安全更新的关键点。

3) Evaluate：只读已准备好的运行时数据，生成姿态

FAnimInstanceProxy::EvaluateAnimation 进入真正图求值。最重要的工程约束是：

  • Evaluate 尽量不要读取不稳定 UObject 状态。
  • 依赖的数据应在 Update 前准备好，并以 Proxy 可安全访问的形式存在。

当团队把“采样”和“求值”混写在同一个蓝图函数里时，随机抖动几乎必现。

4) Notify 与 RootMotion：副作用回到 GameThread

TriggerAnimNotifies（:1548）和 ConsumeExtractedRootMotion（:3855）体现了一个常被忽略的事实：

  • 动画求值是数学过程。
  • 事件触发与移动回写是游戏逻辑副作用。

这两者必须在时序上被稳定串起来。否则会出现“画面对了，逻辑慢一拍”或“逻辑触发了，画面还没到位”。

工程上的数据契约（建议直接落团队规范）

  1. UAnimInstance 只做输入采样和高层流程控制，不做重计算。
  2. 可线程化计算放 NativeThreadSafeUpdateAnimation，只依赖确定性输入。
  3. Proxy 中存放每帧求值必要的数据快照，避免跨线程临时读 UObject。
  4. Notify 处理逻辑保持幂等，避免同帧重复触发副作用。
  5. Root Motion 只保留一条“权威消费路径”，避免角色移动层重复叠加。

常见错误与反例

错误 1：ThreadSafeUpdate 里直接访问 Controller/Actor 复杂行为

短期看“能跑”，压力场景下容易出现竞态或不可复现异常。

错误 2：EventGraph 同时承担采样和推导

导致你无法回答“这个值是采样值还是推导值，发生在 GT 还是 Worker”。

错误 3：把 Notify 当作严格实时时钟

Notify 是时间线事件，不是网络权威时钟，服务端玩法触发仍需权威路径兜底。

最小验证步骤

  1. 在自定义 AnimInstance 里打印以下函数的线程 ID 与帧号：
    NativeUpdateAnimation、NativeThreadSafeUpdateAnimation、TriggerAnimNotifies。
  2. 把速度/加速度等输入分成两组：
    采样变量（GT写） 与 求值变量（Evaluate只读）。
  3. 人为在 ThreadSafe 路径访问一个明显不安全对象，观察编译警告或运行异常，形成反例记忆。
  4. 对比两套实现：
    全在 EventGraph 计算 vs GT采样 + ThreadSafe 计算，记录主线程耗时与稳定性。
  5. 用 a.ParallelAnimUpdate 0/1 重放同一场景，确认逻辑是否仍完全一致。

预期结果：你会得到一条可重复的“线程安全基线”，后续再扩动画功能时不再靠运气。

小结

Proxy 不是“多余抽象”，它是 UE5 动画并行化的基础契约。
把 UAnimInstance 当作“输入与生命周期外壳”，把 FAnimInstanceProxy 当作“可并行运行时视图”，很多顽固问题会自动消失。
