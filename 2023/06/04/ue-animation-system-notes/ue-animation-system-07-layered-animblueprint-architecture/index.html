系列定位：UE5 动画系统源码拆解（5.5）
本文主题：把复杂角色动画拆成可演进的分层结构，降低单图复杂度（源码长文版）

核心问题

中后期项目里，AnimBlueprint 最大风险不是“不会写节点”，而是“架构失控”：
一个巨型主图同时承载移动、战斗、受击、装备、IK、表情，最终任何改动都全图回归。

UE5.5 给了三种分层工具，但很多项目只用其一：

  1. Linked Anim Layer：按能力接口切换实现。
  2. Sub Anim Instance / Linked Anim Graph：按子图职责拆运行时实例。
  3. Post Process AnimBP：在主图后追加 IK/修正层。

真正的难点是定义层间契约，而不是“会不会连线”。

主线图

这三层在源码里如何协同

1) Linked Layer：接口化扩展，不改主图拓扑

LinkAnimClassLayers 会把目标类中的层实现挂接到当前实例的对应层接口上。
优势是：

  • 主图结构稳定。
  • 能力差异通过类切换实现。

这非常适合武器/职业/形态变体，减少“复制多份主图”的灾难。

2) Linked/Sub Graph：运行时子实例拆分复杂职责

FAnimNode_LinkedAnimGraph::DynamicLink 会在运行时完成链接，随后子图按自己的 Update/Evaluate 节奏执行。
本质上你获得的是“可组合子实例”，而不是简单函数调用。

风险点：

  • 输入输出契约不清晰时，子图会偷偷依赖主图状态。
  • 调试时必须知道当前断点属于哪个实例上下文。

3) LinkedInputPose：跨图姿态传递的桥

FAnimNode_LinkedInputPose 的 CachedInputPose 机制是层间姿态传递关键。
这就是为何某些看似“主图没问题”的 bug，实际发生在输入姿态缓存失配上。

4) Post Process：后置修正层，不应承担主逻辑

USkeletalMeshComponent 会在满足条件时创建并更新 PostProcessAnimInstance（:1227、:1629、:2334）。
这层非常适合：

  • IK（足底、手部对齐）。
  • 程序化微调（武器瞄准偏移、动态修正）。

不建议把核心状态机逻辑塞进 Post Process，否则会破坏调试与职责边界。

分层契约模板（可直接落地）

  1. Base 层只输出“可复用基础姿态”，不感知具体武器能力。
  2. Ability 层只消费规范化输入，不反向修改 Base 内部状态。
  3. PostProcess 只做后置修正，不引入高层状态决策。
  4. 层间只传数据，不传行为对象引用。
  5. 所有层都能在单独开关下独立回归。

最小验证步骤

  1. 从现有主图抽离一个“能力层”（如双手武器），主图保持不变。
  2. 使用 LinkAnimClassLayers 在运行时切换能力类，验证行为变体生效且基础移动不回归。
  3. 把 IK 与姿态微调迁到 Post Process，比较迁移前后主图复杂度和定位效率。
  4. 用标签接口获取 linked 实例（GetLinkedAnimGraphInstancesByTag）做调试确认。
  5. 统计拆分前后：节点数、编译时间、改动影响面、回归用例数量。
  6. 固化层间契约文档，并作为后续功能评审门槛。

预期结果：你会把“巨图维护模式”转成“模块化演进模式”。

小结

分层的价值不是漂亮架构图，而是把动画系统变成可长期演进的工程资产。
当 Linked Layer、Sub Instance、Post Process 各司其职，新增玩法不会再持续污染主线动画。
